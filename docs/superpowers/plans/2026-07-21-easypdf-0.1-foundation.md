# easypdf-rust v0.1 Foundation -- Phase 1 Initial Implementation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从零构建 easypdf-rust 的核心骨架，实现 PDF 创建、读取、合并、拆分、旋转、重排、Markdown 转换、表单填充、资源限制、事件系统等基础能力，建立 `EasyPdf` 门面 API 和 `#[derive(PdfModel)]` 过程宏，完成首批 69 个测试。

**Architecture:** 单一 Cargo workspace，初期约 22 个 crate（后在 v0.2 合并为 9 个）。核心分层：`easypdf`（门面）、`easypdf-core`（模型/错误/IO）、`easypdf-reader`（lopdf 读取）、`easypdf-writer`（printpdf 写入）、`easypdf-derive`（过程宏）、`easypdf-markdown`（Markdown 转换）。

**Tech Stack:** Rust edition 2024, rust-version 1.88, printpdf 0.8, lopdf 0.34, proc-macro2/quote/syn（derive）, pulldown-cmark（Markdown）。

## Global Constraints

- `#![deny(unsafe_code)]` 在每个 crate 的 `lib.rs` 中声明。
- 所有公共 API 返回 `Result<T, PdfError>`，不 panic。
- PDF 写入使用原子文件输出（temp file + rename）。
- 页面索引采用零基（zero-based），内部转换为 PDF 1-based。
- 不引入外部 C/C++ 依赖，纯 Rust 实现。

## 状态核对说明

核对依据：
- `easypdf-core/src/error.rs` -- `PdfError` 枚举定义，含 Io / Parse / InvalidPdf / UnsupportedFeature / Encryption / Signature / SecurityViolation 等变体
- `easypdf-core/src/model/pdf_block.rs` -- `PdfBlock` 枚举定义（初始 Heading / Paragraph / List / Table / Image 5 个变体，后扩展至 14）
- `easypdf-core/src/content.rs` -- `PdfText` / `PdfFont` / `PdfImage` / `PdfTable` / `PdfTableCell` 类型定义
- `easypdf-core/src/io/ssrf_guard.rs` -- SSRF 防护实现
- `easypdf-reader/src/reader/` -- `PdfReader` 实现，含 `extract_text` / `extract_metadata`
- `easypdf-reader/src/strategy.rs` -- `ReadStrategy` 枚举（Full / Lazy / Streaming / auto）
- `easypdf-reader/src/manipulate.rs` -- `merge_files` / `rotate_page` / `reorder_pages`
- `easypdf-writer/src/writer.rs` -- `PdfWriter` 实现，含 `write_text` / `add_page` / `finish`
- `easypdf-writer/src/lib.rs` -- `PdfWriteHandler` trait
- `easypdf-markdown/src/markdown_profile.rs` -- `MarkdownProfile` 枚举（Gfm / Llm / Plain）
- `easypdf-derive/src/lib.rs` -- `#[derive(PdfModel)]` 过程宏
- `easypdf/src/lib.rs` -- `EasyPdf` 门面 API（create / read / manipulate）
- `easypdf/src/builders.rs` -- Builder 类型（PdfCreateBuilder / PdfSplitBuilder / PdfManipulateBuilder）

与 roadmap 出入：
- roadmap 0.1 标注 `#![forbid(unsafe_code)]`，但实际代码使用 `#![deny(unsafe_code)]`。`deny` 可被 `#[allow(unsafe_code)]` 局部覆盖，`forbid` 不可。这是一个细微但有意义的差异。
- roadmap 0.1 标注 "22-crate-to-9-crate workspace consolidation"，但此合并实际发生在 v0.2 阶段（Phase 1 时仍是 ~22 crate）。roadmap 将合并归入 0.1 是事后重新组织的结果。
