# easypdf-rust v0.3 Architecture Consolidation -- 22-to-9 Crate Merging + Security + MCP + Release

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 22 个细粒度 crate 合并为 9 个聚焦 crate，重建 feature 体系，实现 Streaming 读取策略、CMap/ToUnicode 支持、WriteBackend 选择、ProcessorPipeline、4 云 OCR 引擎、MCP server、resident daemon、ISO 32000 加密签名、tracing 可观测性、cargo-fuzz、91.61% 覆盖率，最终发布 v0.1.0 到 crates.io。

**Architecture:** 9 crate 分层：easypdf（门面）/ easypdf-core（模型+IO+加密+事件）/ easypdf-derive（过程宏）/ easypdf-reader（读取+操作+streaming）/ easypdf-writer（写入+后端+字体+图片+形状）/ easypdf-markdown（Markdown 处理+OCR 集成）/ easypdf-ocr（4 云 OCR 引擎）/ easypdf-runtime（MCP+resident daemon）/ easypdf-test（集成+parity 测试）。

**Tech Stack:** Rust edition 2024, rust-version 1.88, printpdf 0.8, lopdf 0.34, ring 0.17（签名 RSA）, x509-parser（证书）, aes / cbc / sha2 / md5 / hmac（加密）, reqwest blocking（OCR HTTP）, serde_json（MCP JSON-RPC）, tracing + tracing-subscriber（可观测性）, cargo-fuzz（模糊测试）。

## Global Constraints

- 合并后每个 crate 保持单一职责，不引入循环依赖。
- feature 体系重建：修复 `ocr` feature 静默激活 `http-base` 的 bug；`markdown-table` / `render` / `ocr` 启用 `easypdf-markdown` 内子模块而非独立 crate。
- `resident` 和 `mcp` feature 移至 `easypdf-runtime`。
- 所有加密操作使用 ring 常量时间 RSA（修复 Marvin Attack / RUSTSEC-2023-0071）。
- SSRF 防护覆盖 IPv6（loopback / ULA / link-local / IPv4-mapped）。
- API key 在 Debug 输出中脱敏。
- 每个 crate 的 `lib.rs` 声明 `#![deny(unsafe_code)]`。
