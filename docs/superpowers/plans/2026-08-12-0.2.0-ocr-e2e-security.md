# v0.2.0 OCR 端到端与安全剩余 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: rust-testing, rust-web-security

**Goal:** 完成 OCR 端到端集成（图片区域识别 → Markdown 输出）和安全剩余项（PDF/A 基础校验），使 OCR 能力从"引擎就绪"升级到"用户可用"。

**Architecture:** 主要修改 `easypdf-markdown`（OCR 集成）和 `easypdf-reader`（PDF/A 基础校验）。OCR 引擎（`easypdf-ocr`）已就绪，需接通 Markdown 转换管道。

**Tech Stack:** Rust 1.88+, reqwest blocking（OCR HTTP）

## Global Constraints

- 保持 `#![deny(unsafe_code)]` 策略。
- 不破坏现有 1522 测试。
- OCR 真实集成需网络访问（测试用 mock）。
- PDF/A 校验仅覆盖基础规则（完整校验在 v0.3.0）。

## 关键发现（代码核对）

- OCR 引擎已就绪（GLM / Hunyuan / Baidu / DeepSeek），但 Markdown 转换中的图片 OCR 集成未端到端接通。
- `validate_pdfa()` 基础方法存在（`crates/easypdf-reader/src/manipulate.rs:260`），但仅检查加密和 XMP，不检查嵌入字体等。
- SSRF 防护已覆盖 IPv6，但无 DNS rebinding 和重定向防护。
- 解压炸弹防护已移除 64KB 豁免，但无速率监控。
